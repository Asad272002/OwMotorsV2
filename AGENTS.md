# OW Motors Project Instructions

## Project Overview

OW Motors is a multi-brand motorcycle dealership website offering:

- TARO
- Lifan
- Hi-Speed
- Super Star

The `../figma-vite-reference` folder contains a React/Vite website generated by Figma Make.

The Figma project is a read-only visual and interaction reference.

Never modify, reorganize, delete, format, or install packages inside `figma-vite-reference`.

All production work must be performed inside `ow-motors-nextjs`.

---

## Primary Technology

Use:

- Next.js App Router
- TypeScript
- Tailwind CSS
- React Server Components
- Supabase PostgreSQL
- Supabase Storage
- Supabase Auth for administrators
- Zod for validation
- Next.js Server Actions or Route Handlers
- next/image
- next/font
- Lucide React where suitable

Only install additional dependencies when they are genuinely required.

Do not copy all dependencies from the Figma Vite project.

---

## SEO Is The Highest Priority

SEO must never be sacrificed for animation, convenience, or visual implementation.

Use Server Components by default.

The following content must be included in server-rendered HTML:

- Page titles
- H1 and section headings
- Brand names
- Brand descriptions
- Motorcycle names
- Motorcycle descriptions
- Prices
- Availability
- Specifications
- Features
- Breadcrumbs
- Category links
- Brand links
- Product links
- FAQ content

Never load essential page content only through:

- useEffect
- Client-side API requests
- Browser-only state
- JavaScript-triggered interactions

Interactive components may enhance server-rendered content, but must not replace it.

---

## Client Components

Use `"use client"` only for isolated interactive components such as:

- Mobile navigation
- Motorcycles navigation menu
- Carousels
- Image galleries
- CC selectors
- Color selectors
- Filter controls
- Sort controls
- Dialogs
- Accordions requiring client interaction

Never mark an entire page or root layout as a Client Component unless technically unavoidable.

Keep Client Component boundaries small.

---

## Routing

Use real Next.js routes.

Required routes:

- `/`
- `/brands`
- `/motorcycles`
- `/motorcycles/brand/[brand]`
- `/motorcycles/category/[category]`
- `/motorcycles/[brand]/[slug]`
- `/about`
- `/contact`
- `/admin`
- `/admin/brands`
- `/admin/categories`
- `/admin/motorcycles`
- `/admin/inquiries`

Use `next/link` for internal navigation.

Do not use:

- React Router
- State-based page switching
- `window.location` for normal internal navigation
- Buttons pretending to be links

All important pages must have crawlable URLs.

---

## Catalog URLs

Use permanent indexable landing pages for:

- All motorcycles
- Individual brands
- Individual categories
- Individual motorcycles

Examples:

- `/motorcycles`
- `/motorcycles/brand/taro`
- `/motorcycles/category/sport-bikes`
- `/motorcycles/taro/gp-v3`

Detailed browsing filters may use query parameters:

- `/motorcycles?cc=250`
- `/motorcycles?color=yellow`
- `/motorcycles?availability=in-stock`

Do not create indexable pages for every possible filter combination.

Filtered URLs must have appropriate canonical and robots handling.

---

## Metadata

Every public route must provide:

- Unique page title
- Unique meta description
- Canonical URL
- Open Graph title
- Open Graph description
- Open Graph image where available

Use static `metadata` for static pages.

Use `generateMetadata` for dynamic brand, category, and motorcycle pages.

Every individual motorcycle page must include:

- Product JSON-LD
- Offer JSON-LD where accurate
- Brand information
- SKU
- Price
- PKR currency
- Availability
- Breadcrumb JSON-LD

Never generate fake ratings, reviews, discounts, inventory, or specifications.

## Images

Use `next/image` for content images.

Store production motorcycle images in Supabase Storage or the Next.js public directory as appropriate.

Use descriptive alt text, for example:

`Yellow Taro GP V3 250cc side view`

Do not use vague alt text such as:

- bike
- image
- motorcycle photo

Important product images must not be CSS-only background images.

Use CSS background images only for decorative imagery.

Do not permanently depend on random external Unsplash placeholder images.

Optimize oversized Figma assets before production.

Use:

- SVG for logos and icons
- WebP or AVIF for photography
- PNG only where transparency is required

---

## Fonts

Use `next/font` where possible.

Do not import Google Fonts through remote CSS inside production stylesheets.

Preserve the existing Rajdhani and Inter visual treatment where appropriate.

## Supabase Security

Use separate server and browser Supabase clients.

Never expose:

- `SUPABASE_SERVICE_ROLE_KEY`
- Database passwords
- Private API keys

The service-role key must never:

- Use a `NEXT_PUBLIC_` prefix
- Be imported into Client Components
- Be returned through API responses
- Be committed to Git
- Be logged

Use Row Level Security for all exposed tables.

Public users may:

- Read active brands
- Read active categories
- Read published motorcycles
- Read published variants
- Read public images, features, and specifications
- Submit contact inquiries

Only authenticated administrators may:

- Create inventory
- Update inventory
- Delete inventory
- Publish or unpublish motorcycles
- Manage images
- View private inquiry information
- Update inquiry statuses

Do not rely only on frontend authorization.

---

## Motorcycle Variants

CC and color combinations must be represented as valid product variants.

Each variant can have its own:

- CC
- Color name
- Color HEX
- Price
- SKU
- Stock status
- Quantity
- Images
- Specifications
- Availability message

Changing a CC or color must update:

- Selected variant
- Price
- SKU
- Stock status
- Images
- Specifications

Invalid CC and color combinations must be disabled.

Do not invent variant data.

---

## Forms

Validate all public and admin forms using Zod.

Forms include:

- Contact form
- Motorcycle editor
- Variant editor
- Brand editor
- Category editor

Validate data on the server even when client validation exists.

Add spam protection and rate limiting before production launch.

Return safe user-facing errors without exposing implementation details.

---

## Accessibility

Use semantic HTML.

Interactive elements must support:

- Keyboard navigation
- Visible focus states
- Appropriate ARIA attributes
- Touch targets of at least 44px
- Sufficient color contrast
- Reduced-motion preferences

Dropdowns must remain open when keyboard focus moves inside them.

Color selection must include text labels and must not depend only on color.

---

## Performance

Avoid unnecessary JavaScript.

Do not import an entire UI library for one icon or one component.

Use dynamic imports only when beneficial.

Avoid layout shift by defining image dimensions.

Do not add artificial loading screens.

Do not delay the page for animations.

Respect `prefers-reduced-motion`.

Avoid autoplay animation that consumes excessive resources.

---

## Code Quality

Use:

- TypeScript strict typing
- Reusable components
- Clear naming
- Server-side query functions
- Central validation schemas
- Central database types
- Consistent error handling

Avoid:

- `any`
- Duplicate components
- Huge page files
- Inline hardcoded datasets
- Duplicate Tailwind strings where a reusable component is appropriate
- Unnecessary abstraction
- Premature optimization
